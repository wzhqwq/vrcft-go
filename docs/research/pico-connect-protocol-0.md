# PICO Connect transfer protocol 0: evidence audit

Date: 2026-11-11. Installed client: PICO Connect 10.6.6.0 on Windows.

The [VRCFT PICO guide](https://docs.vrcft.io/docs/hardware/vr/pico/pico4pe) says setting `faceTrackingTransferProtocol=2` is a workaround because Pico4SAFTExtTrackingModule does not support the newer protocol. The [UnifiedPicoModule protocol reference](https://github.com/WolalaQAQ/UnifiedPicoModule/blob/main/docs/protocol.md) covers only the legacy PICO Connect UDP stream on port 29765. PICO's [Unity face-tracking API guide](https://developer.picoxr.com/document/unity/face-tracking/) documents device expressions, not PICO Connect's PC transport.

Read-only inspection of `C:\Program Files\PICO Connect` found version 10.6.6, an OpenVR driver, and an OpenXR runtime manifest. A text search of the installed driver/resource JSON and text files found no transfer-protocol setting, face-data endpoint, packet schema, or field ordering. The actual user configuration file on this installation is `%APPDATA%\PICO Connect\settings.json`, with the setting nested under `lab`; the singular `setting.json` path in the VRCFT guide does not exist here. The OpenXR manifest alone does not prove it exposes face data to a separate plugin.

During a live PICO Connect 10.6.6 / SteamVR session on 2026-11-11, `lab.faceTrackingMode=4` and `lab.faceTrackingTransferProtocol=2` sent 362 datagrams in five seconds to a temporary loopback listener on port 29765. All were 912 bytes with header tracking type 2. After the user changed the transfer setting to 0 and restarted/reconnected, six seconds of loopback listening on ports 29765 and 29763 received no datagrams. The PICO Connect process still owned loopback UDP endpoints 39869 and 39870, which appear to be internal control endpoints, but their purpose was not verified. No biometric payloads or values were saved. This comparison establishes only that protocol 0 does not use the known legacy output ports in the observed session.

Protocol 0 remains unidentified. A complete receiver requires either an official PC interface specification or a real PICO 4 Pro/Enterprise session with protocol 0 enabled that identifies the endpoint/API, byte or call structure, source clock, validity, and shape order. Do not infer the protocol from the 29765 legacy stream. Any temporary biometric capture needs device-user consent and must stay outside this repository; only redacted structure and derived contract should be committed.

The installation contains `ps_pico_connect_external_sdk.dll`, whose export table exposes a C++ `PICOConnectExternalInterface::Create` symbol. No public header or documentation for its callback methods was found in the installation or initial web search. This symbol is a possible research lead, not evidence that the interface provides face data or is stable enough for a bundled plugin.
