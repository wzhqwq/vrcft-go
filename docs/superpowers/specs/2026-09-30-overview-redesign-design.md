# 概览界面重设计

**日期：** 2026-09-30
**状态：** 待审阅

## 背景与目标

当前概览将应用阶段、Avatar、OSC、计划、插件摘要、重要插件和错误分成多张卡片，正常状态下重复信息较多，也容易让面积较大的卡片只承载一两项事实。本设计将概览固定为两个主题：角色驱动状态，以及输入输出控制。用户打开页面时，应能判断当前 Avatar 可由软件驱动哪些参数、此刻有多少参数正由有效插件输入驱动，并快速处理插件或 OSC 问题。

目标：

- 将 Avatar 与计划合并，显示软件可驱动参数数量和当前插件驱动参数数量。
- 用模态框列出软件可驱动的参数，并逐项标明当前驱动状态。
- 在固定布局内按状态改变内容和颜色，不通过重新排列卡片突出故障。
- 概览提供最多三个插件的关键状态、输出能力图标和快捷开关；OSC 只展示状态和设置入口。
- 将全局导航改为常驻顶部、左对齐的图标加文字导航；页面入口使用明显按钮。
- 保持 `640×480` 窗口可用，不以空白撑高内容较少的区域。

不包括插件安装、OSC 控制、追踪数值图表、参数实时数值或历史趋势。本项目尚未发布；插件偏好文件的旧格式不要求兼容或迁移。

## 页面结构

采用已选定的“角色焦点 + 侧边控制台”布局：

- 宽窗口中，左侧为角色驱动区域，右侧依次为插件输入和 OSC 输出。左侧稍宽；两侧内容按自身高度排布，不强制等高。
- 窄窗口中，两块主题按角色、插件、OSC 的顺序纵向排列。页面只允许纵向滚动；长名称、地址及参数名不造成页面横向溢出。
- 页标题保持简短。应用阶段不再单独占一张正常状态卡片；只有影响使用的阶段或错误才进入对应区域的状态文案。
- 故障区域原位换色，并显示具体原因和可执行按钮；另一块可用的信息保持可见。状态还要有文字和图标，不能只依赖颜色。

`AppShell` 在所有支持的窗口宽度都使用顶部主导航。导航按钮带图标和文字，左对齐且保持可读宽度；空间不足时导航自身横向滚动。它仍是跨页面的 `nav`，不改成页面内部的 ARIA tab 控件。导航和概览内的页面入口共用 `App` 的导航逻辑，因此设置页未保存内容的离开确认继续生效。

## 角色驱动区域

角色区显示当前 Avatar 名称；仅在必要时提供 ID 的复制入口。计划来源和状态用短文案表达，不在正常视图堆叠路径、代次或内部配置 ID。

| 状态 | 区域内容 |
|---|---|
| 正常、计划就绪且有参数 | Avatar 名称；“当前驱动 X / 可驱动 Y”；“查看参数列表”按钮。 |
| 计划就绪但没有可驱动参数 | 明确说明该 Avatar 没有请求软件支持的驱动参数；不显示可打开的空列表。 |
| 尚无 Avatar | 说明正在等待 Avatar；不显示虚假的零计数。 |
| Avatar 已知、计划尚未就绪 | 显示正在准备计划；尚无可信列表时不显示计数。 |
| 计划失败或缺少配置 | 原位使用警示色，显示可理解的原因；缺少配置时给出“前往设置”按钮。 |
| 运行时数据过期 | 保留最近可信内容并标明“数据可能已过期”；不把旧计数称为实时值。 |

参数列表模态框只展示当前计划中被软件识别并编译成功的 VRCFT 参数。每项展示稳定的参数名称和“当前驱动”或“暂无有效输入”；不列出 Avatar JSON 中与软件无关的参数，也不显示追踪值。模态框可滚动，具备标题、关闭按钮、焦点管理和键盘操作。计数和列表必须来自同一计划代次与同一状态快照。

## 当前驱动的判定

“可驱动”集合是当前就绪计划的 `ParameterIDs()`：它来自成功编译的 OSC 绑定，去重并按稳定参数 ID 排序。可驱动数量为该集合长度。

“当前插件驱动”表示参数所需的每项输入在现有有效期内都收到有效插件数据，并且该参数可成功求值。后端对每个请求参数使用现有参数依赖解析取得叶子输入，结合当前代次的合并帧、输入有效掩码、处理后的有效性和求值结果判定：

- 需要的 Eye、Expression、Lip 组都必须在当前处理配置的有效期内保持活跃；需要的具体 Eye 或 Expression 字段必须有效。
- 组合参数的所有依赖都必须满足。布尔追踪活跃参数也必须有对应组的近期有效输入；求值器返回一个有效的 `false` 本身不表示当前受到驱动。
- 处理流程的保持与衰减值不能在插件停止提供近期有效数据后继续增加“当前驱动”计数。
- Avatar 代次切换时立即清除上一代次的驱动标记，直到新代次取得有效输入。OSC 连接状态不参与这个计数。

后端在现有协调器内计算一份低频、只读的摘要：计划代次、参数名称、每项是否当前驱动以及汇总数量。状态变化和有效期届满都能更新摘要，但不通过 Wails 发布逐帧数据；界面更新被限速到适合状态展示的频率。运行时状态、Wails DTO 和前端映射只传递参数身份与布尔结果，不传递原始追踪值、插件私有配置或来源路径。

## 输入输出控制区域

插件面板最多展示三个插件。每行有插件名称、生命周期状态、运行时帧率、支持的输出能力图标和快捷开关；停用或无帧时不显示帧率。Eye 使用眼镜图标，Expression 使用人脸图标，Lip 使用口型相关图标。图标代表插件**声明支持**的能力，不代表此刻正在输出的数据；每个图标具有文字提示和无障碍名称。面板底部使用“查看全部插件”按钮。

插件选择按故障、恢复中、工作中、其他状态的顺序；同一状态组按“最近手动打开开关时间”倒序，从未打开过则用“首次发现时间”，之后按名称、ID 排序。筛选与排序只决定概览的三个快捷项，不改变插件页现有筛选和分页语义。没有插件时用紧凑空状态和“查看插件”按钮；插件数据过期时保留快照并标记过期。

OSC 面板只显示发现／连接状态、实际目标（有目标时）和“前往设置”按钮。没有目标、正在发现和连接失败分别用相应短文案。OSC 错误只改变本面板，不让角色驱动计数消失。

## 持久化与接口

现有插件偏好只存 `enabled` 和插件配置。本设计在插件偏好中增加 `installedAt` 与可为空的 `lastEnabledAt`：

- `installedAt` 为应用首次发现插件并持久化记录的时间，不使用文件修改时间。
- 用户成功将开关从关切到开时，写入 `lastEnabledAt`；重启后自动恢复已启用状态、自动重试或重复打开请求不更新该值。
- 时间持久化使用统一 UTC 表示。新格式直接覆盖旧的开发期插件偏好数据，不编写迁移逻辑；旧配置的启用状态和插件私有设置不保证保留。
- 插件列表 DTO 增加两个时间字段供概览排序，仍遵守现有插件数量与字符串边界。

运行时状态和 DTO 增加当前计划的有界参数摘要。前端只负责展示、模态框状态和概览选择；参数依赖、有效性与代次约束由 Go 后端统一计算。插件开关仍通过现有 `PluginsModule.setEnabled`，按钮式页面入口通过现有应用导航回调。

## 错误处理与验收

运行时与插件模块继续独立加载、失败和保留最近快照。无可信计划时参数列表不可用；摘要与当前计划代次不符时不展示旧驱动标记。快照过期时提供明确标记。单个插件开关失败仅反馈在对应插件行或面板，不抹去其他区域。

验收重点是正常、空计划、配置缺失、断流、计划切换、OSC 故障和独立模块过期时的内容；参数总数与逐项状态一致；排序在时间并列时稳定；`640×480` 下导航、按钮和模态框可操作且无页面横向溢出。按用户要求，不安排旧格式迁移或回归测试；实现阶段只对新增计算与交互做必要的定向验证，并运行前端类型检查和构建。
